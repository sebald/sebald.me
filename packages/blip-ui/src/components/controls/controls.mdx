# Controls

The touch versions of a game's keys. On the tall stage (a phone held
upright) a bar along the bottom, `--bui-bar` tall; on the wide stage small
pixel buttons in the corners. It knows no buttons of its own: you pass them
as `start` and `end`.

## Anatomy

1. **Start**, the top left corner, or the left of the bar: Back or Pause
2. **End**, the top right corner, or the right of the bar: sound, fullscreen
3. **Bar**, along the bottom of the tall stage, with a line above it

## Layouts

| Layout | Where                                                 | Shown                           |
| ------ | ----------------------------------------------------- | ------------------------------- |
| Wide   | Corners, 5 stage pixels in. `startAt` centres `start` | For touch (`show="touch"`)      |
| Tall   | A bar of `--bui-bar` along the bottom of the stage    | Always, it is the touch control |

On the tall stage the `Stage` writes `--bui-bar` (its `bar` prop, 52 CSS
pixels), so screens keep clear of it: pad by `var(--bui-bar)`. Elsewhere it
is 0.

## Usage

- **Do** pass `IconButton`s and `IconToggle`s, with `variant="bar"` on the
  bar. Choose the variant from `usePixels().tall`.
- **Do** keep the keys in the game. Controls has none: bind Esc and M with
  `useKeys` and have the buttons call the same actions.
- **Don't** put more than two or three buttons in a slot.

```tsx
const { tall } = usePixels();
const variant = tall ? 'bar' : 'corner';

useKeys({ Escape: back, m: toggleSound });

<Controls
  start={
    <IconButton
      variant={variant}
      icon="back"
      label="Back"
      aria-label="Back (Esc)"
      onClick={back}
    />
  }
  end={
    <IconToggle
      variant={variant}
      icon="soundOff"
      pressedIcon="soundOn"
      aria-label="Sound (M)"
      pressed={sound}
      onPressedChange={toggleSound}
    />
  }
/>;
```

## Input

Corners show for touch only: `useInputKind` follows the last input, so a
keyboard player never sees them. The tall bar is always there.

## Accessibility

- Each button is a native `<button>` with an `aria-label`
- Tab order follows the DOM: start, then end
