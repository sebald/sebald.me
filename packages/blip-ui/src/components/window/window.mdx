# Window

The quiet window every text sits in: the opponent's line, the menus, the
results, a picker's description box. It grows with what is in it; the
screen positions and sizes it.

## Anatomy

1. **Ink**, the outline, with the stepped corners `[3, 1, 1]`
2. **Frame**, a pale ring one step in (`--bui-frame`)
3. **Inner ring**, dark, one more step in (`--bui-frame-inner`)
4. **Fill**, `--bui-surface` with a dithered gradient: a lit row under the
   frame fading in halves, quarters and eighths of dots, the same in shade
   up from the bottom
5. **Legend**, optional, the control hints along the bottom edge: a
   `Legend` as the window's last child

## Usage

- **Do** put all text that the player reads on the stage in a window, so it
  stays readable over any scene.
- **Do** give a window that takes input a legend that names the keys.
- **Do** use Tabs with `variant="window"` for a window with pages, not a
  Window with tabs put on it.
- **Don't** nest windows. A description box sits beside its window, not in it.
- **Don't** clip what's inside: the content is never cut at a corner, so
  keep it inside the padding.

## Legend

`Legend` shows what works right now: the keys while the player uses keys,
one line for touch after a tap. Put it last in the window, as a child: it
sits along the bottom edge by itself. `CornerLegend` puts it in the stage's
bottom right corner; held upright, it centres over the bar of controls.

## The pixel

The frame is drawn in stage pixels; the padding inside it is 4 `--bui-px`,
the stage pixel never finer than 3 CSS pixels, because on a phone's tall
stage a stage pixel is too fine to keep the text off the frame.
