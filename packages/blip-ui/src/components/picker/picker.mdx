# Picker

A list the player moves through with a cursor: the title menu, options,
the choices in a duel. It is always open and always listening, and
with several on a layer it listens for the one the player is in. Lists of
choices are a Picker, not a column of buttons. It is built from its parts, so the JSX reads like the menu,
and its window's title is its name:

```tsx
<Window>
  <Title>Options</Title>
  <Actions>
    <Picker>
      <PickerSetting id="mode" value="Normal" onStep={step}>
        Mode
      </PickerSetting>
      <PickerItem id="hard" disabled note="Beat the Stakeholder first." onSelect={…}>
        Hard mode
      </PickerItem>
      <PickerGroup>
        <PickerItem id="back" variant="back" onSelect={close}>
          Back
        </PickerItem>
      </PickerGroup>
    </Picker>
  </Actions>
  <Legend keys={[['↑↓', 'choose'], ['Enter', 'confirm']]} touch="Tap a line" />
</Window>
```

## Anatomy

1. **Cursor**, a pixel triangle on the current row
2. **Row**, the label; the current one is white, an accent one is primary
3. **Rail**, beside a list that does not fit: an arrow lit where there is
   more, and a track with the view's place on it
4. **Note**, a small window beside the list's own, at the current row

## Parts

| Part            | What it is                                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `PickerItem`    | Something to pick                                                                                                      |
| `PickerSetting` | A setting: its name and its value between the step arrows, shown on the cursor's row; left and right step it (Setting) |
| `PickerGroup`   | Items that belong together, with room above them                                                                       |

## Variants and states

<Canvas of={PickerStories.Overview} />

| Prop               | Effect                                                                         |
| ------------------ | ------------------------------------------------------------------------------ |
| `variant="accent"` | The loud one: primary colour, blinking (steady under reduced motion)           |
| `variant="back"`   | It leaves: Back or Cancel, which sound like stepping back, not like confirming |
| `disabled`         | Dimmed and reachable, but it bumps when picked. Give it a `note` why           |
| `ruledOut`         | From 0 to 1, how far a hint has ruled it out: it fades, still there to pick    |
| `note`             | What it does, or why it is off, in a window beside the list                    |

## Usage

- **The title names the menu**, as on the SNES, where a list had no
  label of its own: the name the player reads is the one a screen reader
  says, so the two can't drift apart. A `label` given wins over the
  title, for a menu straight on the stage or a window whose title says
  something else (`Gold: 120` over a shop).
- **Back is the last item**, `variant="back"` in a `PickerGroup` of its
  own, and Esc does what it does; in a form it is a button instead
  (`Button`, Back, shows both).
- **Do** put a picker in a Window, with a Legend that names the keys.
- **Do** keep a disabled item in the list and say why in its note.
- **Don't** hide what is not available. Nothing in a menu is hidden.
- **Don't** switch a picker off for a `Dialog` (or a `Confirm`) over it.
  A dialog is a layer of its own: the menu under it hears no keys until
  it closes, without turning its `active` off.
- **Do** leave several pickers on one layer as they are: they share the
  keys by themselves (see Input). The list itself is what a click or the
  pointer hands the keys over by, not the Window around it.

## The description box

The note is rendered into the closest `[data-stage]` (what `Pixels`
sets), so no window can cut it off. It goes beside the list's window, on
the right or on the left where the right has no room. The stage's width
is measured. On the tall
layout it goes under the window, as wide as it.

## Input

- Up and down, or W and S, move; the list wraps
- Left and right, or A and D, step a `PickerSetting`
- Enter or Space picks the current item
- Hovering a row moves the cursor; a click or tap picks it
- Under a finger there is no cursor: only a row with a note is marked

### Several pickers on one layer

The keys go to one: the one the player last pointed at, clicked or moved
the focus into (it keeps them until another is), and until then the first
on the page. A screen with one menu needs no click. The menu without the
keys is at rest: no cursor and no note (one cursor on a screen, as in a
game, never two where one answers). A picker that goes
away hands the keys back. A `Dialog` is a layer of its own, with its own
pick of the keys, so the menu under it hears none.

This follows the web: the keys change hands by pointer or focus (Tab). By
directional input alone, with no pointer, a second menu cannot be
reached; a screen that needs that switches `active` itself (directional
handover waits for gamepad input, Q18).

## Sound

`move` when the cursor moves or a value steps, `confirm` when an item is
picked, `back` for a `back` item and `bump` for a disabled one.

## Accessibility

- A `<ul>` named by its window's or dialog's `Title` (`aria-labelledby`),
  or by `label` where it has one, with a button per row; the current one has
  `aria-current`, a disabled one `aria-disabled`
- The note is an `aria-live` region
- The focus mark (`foundations/focus.mdx`) is the cursor, always in the
  primary colour (10.51:1 on the window): Tab puts the cursor on the row it
  reaches, so there is one cursor and a row does not grow an outline.
  2.4.7 and 1.4.11 pass. 2.4.13 (AAA) fails: a pointer 3 by 5 pixels is
  smaller than a 2 pixel line round the row
- A picker with no name, no title over it and no `label`, is refused
  while building, with a message in the console
