# Button

A pixel button, for the actions a screen offers outside its menus: Start
under the role picker, Play fullscreen on the turn screen. Lists of
choices are a Picker, not a column of buttons.

## Anatomy

1. **Ink**, the outline every sprite and window has, with the window's
   stepped corners (`[3, 1, 1]`)
2. **Key**, one step in: the face, with a light row along its top and a
   shade row along its bottom
3. **Cursor**, focused only: the menus' gold pointer, left of the button

## Variants

| Variant       | Looks like                                                              | When to use                                                                                                      |
| ------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `primary`     | A paper key, ink letters: stands out on a window and on the stage alike | The one action the screen is for. One per screen. Not yellow: yellow says "look here" (`foundations/colour.mdx`) |
| `secondary`   | A muted key a step lighter than the window, light letters               | Beside a primary: back, options, cancel                                                                          |
| `destructive` | The key in the danger colour                                            | What can't be undone: quitting a run, resetting progress. Ask first                                              |

## Sizes

`default` is 44 CSS pixels tall at least, a thumb's height (WCAG 2.5.5).
`small` is for dense menus where a pointer aims; don't use it where the
screen can be touched.

## Usage

- **Do** give a screen one primary button. Pair it with a secondary for the
  way back.
- **Do** put buttons in `Actions`: it leaves the room the focus cursor
  needs, left of the first button and between two (12 apart; see
  `foundations/focus.mdx`, the cursor's room).
- **Do** start the label with a verb, or name what starts: _Start_, _Retry_,
  _Play fullscreen_.
- **Don't** use buttons for a list of choices. That's a Picker, with a
  cursor and the keys.
- **Don't** put two primary buttons side by side.

## Back

Back is one thing in a game and two in the kit, by the window it is in.
In a menu it is the list's last item, so the cursor reaches it like any
other and it sounds like stepping back (`Picker`). In a form the rows are
controls, so it is the quieter button beside the main one. Esc is Back in
both, as B was on a pad: the screen gives Escape the handler Back has
(`useKeys`), and a `Dialog` closes on it by itself. In a text field Esc
first lets go of the field; the next one goes back.

## The pixel

The button draws in `--bui-px`: the stage's pixel, but never finer than
`--bui-min-px` (3 CSS pixels). On a phone's tall stage a stage pixel is
barely more than one CSS pixel, and the ink, the steps and the bevel would
thin to nothing. Switch the toolbar's scale to 1x to see it hold.

A key is lit like the icons: a light row along its top and a shade row
along its bottom, one pixel each, so the label sits in the middle.
Pressed, the whole face goes a step darker with the shade along its top, and nothing moves. Swapping the two rows alone was too small a change for a click, which lasts about a tenth of a second: it read as a blink.

## Accessibility

- A native `<button>`, `type="button"` unless set otherwise
- Focus (`foundations/focus.mdx`) shows for the keyboard only
  (`:focus-visible`): the menus' cursor, 3 by 5 pixels in the primary
  colour, 3 seen pixels left of the face (2 from the ink), the same on every variant (a mark
  on the face would change with its colour). It takes no room, so the
  button never grows. 10.51:1 on the window; 2.4.13 (AAA) fails, as a
  `Picker`'s cursor does: it is smaller than the button's perimeter
- The secondary's letters are 6.47:1 on its face; the face is 1.79:1 to
  the window, so its bevel and its label tell it is a button
- Disabled buttons fade and lose their colour; prefer explaining why
  something is locked next to it
