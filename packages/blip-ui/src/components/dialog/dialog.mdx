# Dialog

A window over the stage, for what interrupts a screen: options, a pause,
how it works, a question before something can't be undone. The stage is
dimmed down to the bar of controls, the window sits in the middle, and
while it is open it has the keys: the screen under it hears none. Built
on Base UI's Dialog (focus, Escape, a tap outside, the roles).

```tsx
<Dialog open={open} onOpenChange={setOpen}>
  <Title>Options</Title>
  <Actions>
    <Picker label="Options">…</Picker>
  </Actions>
  <Legend keys={[['Esc', 'back']]} touch="Tap a line" />
</Dialog>
```

## Anatomy

1. **Scrim**, the stage dimmed (`--bui-scrim`), down to the bar of
   controls (`--bui-bar`)
2. **The window**, drawn as a `Window` is; the dialog draws it, so there
   is no `Window` to put in it
3. **Title**, which names it
4. **Content**, what it says: a line or two, a list; it describes it
5. **Actions**, what can be done: a `Picker`, or buttons side by side,
   centred
6. **Legend**, last, along the bottom edge

These are the kit's shared parts (Title, Content, Actions), the same in a
`Window` or a tab's panel; in a dialog its title names it and its content
describes it. The window places them by their slot, in that order, with
the room between them; each part places nothing itself. All of them but the title
are optional: how it works is a title, what it says and a legend, no
actions.

## Usage

The dialog covers the stage, not the part it is placed in, so wherever it
sits inside the stage it is the same window. It takes the keys from the
screen under it by itself, which is why the screen's Picker has no need to
be switched off. A tap outside closes it; for a question that can't be
undone that would be an answer nobody gave, so an `alertdialog` ignores
it. A dialog without a name is a wall: the title is what names it for
everyone, a screen reader included. The large size is for text that is
read, the default for what is answered at a glance.

## Input

- The dialog's own keys (its Picker's, `useKeys` inside it); the screen
  under it hears none until it closes
- Escape closes it, and so does a tap outside (not for an
  `alertdialog`); both sound like going back
- It is modal: a tap on anything else, a corner control or the bar's,
  only closes it and does nothing there, and the page around the game
  holds still while it is open

## Accessibility

- `role="dialog"` or `alertdialog`, named by its title and described by
  its content
- The focus moves into it and stays there, and goes back where it was
  when it closes
